# 服务器操作清单（照着敲）

> 前提：整个 `beijing-wuzi-campus-guide` 已经放到服务器上，比如 `/opt/beijing-wuzi-campus-guide`。
> 下面每一步都是独立的命令块，复制粘贴即可。遇到报错就停下，把报错发给我。

---

## 第 1 步：看清楚旧版是怎么跑的

```bash
sudo ss -lntp | grep ':55 '
```

记下 `pid=xxxx`。再查它是谁拉起来的：

```bash
systemctl list-units --type=service --state=running | grep -iE 'node|campus|bwz|python'
pm2 list 2>/dev/null
```

---

## 第 2 步：确认 Node 和 MySQL

```bash
node -v
mysql --version
```

Node 要 ≥ 18。没有的话：

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
```

MySQL 没有的话：

```bash
sudo apt-get update && sudo apt-get install -y mysql-server
sudo systemctl enable --now mysql
```

---

## 第 3 步：生成两个随机串

```bash
openssl rand -hex 48
```

→ 记作 **A**（JWT 密钥）

```bash
openssl rand -base64 24
```

→ 记作 **B**（数据库密码）

---

## 第 4 步：改配置

```bash
sudo nano /opt/beijing-wuzi-campus-guide/app/.env
```

把这两行改成 A 和 B：

```
DB_PASSWORD=B
JWT_SECRET=A
```

`SERVE_PORT=55` 和 `HOST=0.0.0.0` 保持不变（不用 Nginx 的话）。

按 `Ctrl+O` 回车保存，`Ctrl+X` 退出。

---

## 第 5 步：停掉旧服务并备份

按第 1 步查到的方式选一条执行：

```bash
# 如果是 systemd 服务
sudo systemctl stop 旧服务名 && sudo systemctl disable 旧服务名

# 如果是 pm2
pm2 stop all && pm2 delete all && pm2 save

# 如果是裸进程（用第 1 步的 pid）
sudo kill xxxx
```

确认端口空了：

```bash
sudo ss -lntp | grep ':55 ' || echo "55 端口已空闲"
```

备份旧数据：

```bash
sudo mysqldump -u root -p bwz_campus_guide > ~/old_db_$(date +%F).sql
```

---

## 第 6 步：部署

```bash
cd /opt/beijing-wuzi-campus-guide/deploy
sudo chmod +x deploy.sh
sudo ./deploy.sh
```

看到绿色的「6/6 完成」就好。

---

## 第 7 步：验证

```bash
sudo systemctl status bwz-campus --no-pager
curl -s http://127.0.0.1:55/api/health
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:55/
```

第一条要有 `active (running)`，后两条要返回 `{"ok":true...}` 和 `200`。

---

## 第 8 步：放行端口

```bash
# Ubuntu / Debian
sudo ufw allow 55/tcp && sudo ufw reload

# CentOS / 阿里云 Linux
sudo firewall-cmd --add-port=55/tcp --permanent && sudo firewall-cmd --reload
```

**云服务器还要去网页控制台的「安全组」里加一条：入方向，TCP，端口 55，0.0.0.0/0。**

然后浏览器打开 `http://服务器IP:55`，后台 `http://服务器IP:55/admin`，账号 `admin`，密码 `1234`。

---

## 第 9 步：改掉默认密码

后台右上角改，或者：

```bash
cd /opt/beijing-wuzi-campus-guide/app
sudo NEW_ADMIN_PASSWORD='你的新密码' node server/scripts/reset-admin.mjs
```

## 以后更新（改完代码后）

最省事的方式：把新的 `beijing-wuzi-campus-guide` 整个传上去覆盖旧目录，然后：

```bash
cd /opt/beijing-wuzi-campus-guide/deploy
sudo ./update.sh
```

它会依次：备份当前 dist / server / .env → 更新前端产物 → 同步数据库账号 → **同步内容数据（建筑信息、周边设施等）** → 重启并健康检查。

> 「内容改了但服务器上还是老的」就是这个问题——旧版 `update.sh` 完全不碰数据库。
> 现在内容走 `database/content.json`，`update.sh` 会自动同步，只覆盖 7 张内容表，不动照片、投稿、日志、后台账号。

### 只覆盖文件、直接 `systemctl restart` 的情况

如果你图快，直接把 `beijing-wuzi-campus-guide` 整个传上去覆盖，然后：

```bash
sudo systemctl restart bwz-campus
```

**表结构也会自动补齐**：服务启动时会跑一次结构自检（`server/schema.js`），缺 `location_submissions` 的照片字段、缺 `buildings.aliases` 之类，会自动 `ALTER TABLE` 补上，日志里能看到：

```
[schema] 已补 location_submissions.author_name
[schema] 已补 location_submissions.type 枚举
```

如果日志里是 `[schema] 表结构已是最新`，说明不用做任何事。

万一自检被数据库权限挡住（日志出现 `[schema] 补 xxx 失败`），手动补一次：

```bash
cd /opt/beijing-wuzi-campus-guide/app
node server/scripts/repair-schema.mjs
```

> 「上传照片报服务器内部错误」几乎都是这个原因：服务器上的库还是旧结构，缺投稿的照片字段。
> 补完再试即可，不需要删库。


如果想只同步内容、不动代码：

```bash
cd /opt/beijing-wuzi-campus-guide/app
node server/scripts/sync-content.mjs --dry-run   # 先看会改什么
node server/scripts/sync-content.mjs            # 正式写库
```

### 手动分文件更新（不用 update.sh 时）

本机：

```bash
cd My_school/My_school
npm run build
```

上传（在你电脑上执行）：

```bash
scp -r dist 你的用户名@服务器IP:/tmp/new-dist
scp -r src  你的用户名@服务器IP:/tmp/new-src
scp -r server 你的用户名@服务器IP:/tmp/new-server
scp ../database/content.json 你的用户名@服务器IP:/tmp/content.json
```

服务器上：

```bash
sudo systemctl stop bwz-campus
sudo rsync -a --delete /tmp/new-dist/   /opt/beijing-wuzi-campus-guide/app/dist/
sudo rsync -a          /tmp/new-src/    /opt/beijing-wuzi-campus-guide/app/src/
sudo rsync -a          /tmp/new-server/ /opt/beijing-wuzi-campus-guide/app/server/
cp /tmp/content.json /opt/beijing-wuzi-campus-guide/database/content.json
cd /opt/beijing-wuzi-campus-guide/app && node server/scripts/sync-content.mjs
sudo systemctl start bwz-campus
curl -s http://127.0.0.1:55/api/health
```

⚠️ `--delete` 只能用在 `dist` 上，**绝对不要**对 `public/uploads` 用，那是用户传的照片。

## 出问题看哪里

```bash
sudo journalctl -u bwz-campus -n 80 --no-pager
sudo tail -50 /opt/beijing-wuzi-campus-guide/app/logs/server.err.log
```

想退回上一版：

```bash
sudo systemctl stop bwz-campus
sudo rm -rf /opt/beijing-wuzi-campus-guide/app/dist
sudo cp -a /opt/beijing-wuzi-campus-guide/deploy/backup_时间戳/dist /opt/beijing-wuzi-campus-guide/app/dist
sudo systemctl start bwz-campus
```
