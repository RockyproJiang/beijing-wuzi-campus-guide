# 部署说明（Linux 服务器）

面向你现在的场景：**服务器上已经有一个旧版在跑、占着 55 端口，要把它换成本版**。

下面每一步都是可以直接复制粘贴的命令。请按顺序执行。

---

## 0. 先确认登录方式

你需要一个能 `sudo` 的账号。下文所有命令都以 `root` 或 `sudo` 执行。

```bash
ssh 你的用户名@你的服务器IP
```

先看一眼旧服务是怎么跑的（**这一步很重要，决定了第 5 步怎么停它**）：

```bash
sudo ss -lntp | grep ':55 '
```

输出里会显示占用 55 端口的进程名，例如：

```
LISTEN 0 511 127.0.0.1:55 0.0.0.0:* users:(("node",pid=12345,fd=21))
```

记下这个 **pid** 和进程名。如果是 `node`，再看它是不是被 systemd / pm2 / screen 托管的：

```bash
# 被 systemd 托管的话会看到 service 名
systemctl list-units --type=service --state=running | grep -iE 'node|campus|bwz'
# 被 pm2 托管的话
pm2 list
```

## 1. 安装 Node.js（已装可跳过）

```bash
node -v
```

要求 **18 或更高**。没有或版本太低，用 NodeSource 装 20 LTS：

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v
```

> CentOS / RHEL / Alibaba Cloud Linux 用：
> ```bash
> curl -fsSL https://rpm.nodesource.com/setup_20.x | sudo bash -
> sudo yum install -y nodejs
> ```

```bash
mysql --version
```

```bash
sudo apt-get update && sudo apt-get install -y mysql-server
```

## 3. 上传文件

把整个 `beijing-wuzi-campus-guide` 文件夹传到服务器，比如放到 `/opt/`。

**方式 A：在你自己的电脑上执行（推荐，最简单）**

```bash
# 在 Windows 的 PowerShell 或 CMD 里，进到项目所在目录的上一级
scp -r beijing-wuzi-campus-guide 你的用户名@你的服务器IP:/tmp/
```

**方式 B：用图形工具**
WinSCP / FileZilla / MobaXterm 连上去，直接把文件夹拖到 `/tmp/`。

然后到服务器上把它移到正式位置：

```bash
sudo mv /tmp/beijing-wuzi-campus-guide /opt/
sudo chown -R root:root /opt/beijing-wuzi-campus-guide
ls /opt/beijing-wuzi-campus-guide
```

你应该看到 `app  blender  database  deploy  docs  README.md`。

## 4. 改配置（**上线前必做**）

### 4.1 生成一个随机密钥

```bash
openssl rand -hex 48
```

复制输出的那串（96 个字符），下面要用。

### 4.2 改数据库密码（建议）

```bash
openssl rand -base64 24
```

复制这串，作为数据库密码，下面也要用。

### 4.3 编辑 `.env`

```bash
sudo nano /opt/beijing-wuzi-campus-guide/app/.env
```

按 `i` 进入编辑，把下面几项改成你的值：

```ini
NODE_ENV=production

SERVE_PORT=55
HOST=127.0.0.1

DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=bwz_campus_guide
DB_USER=bwz_app
DB_PASSWORD=这里换成第 4.2 步生成的密码

JWT_SECRET=这里换成第 4.1 步生成的 96 位随机串
```

改完按 `Esc`，输入 `:wq` 回车保存。

> `HOST=127.0.0.1` 表示只监听本机，由 Nginx 转发（推荐）。
> 如果你**不用** Nginx、想让 Node 直接对外提供服务，把 `HOST` 改成 `0.0.0.0`。

### 4.4 同步数据库密码

`.env` 里的 `DB_PASSWORD` 改了，建库脚本里的也要改，否则第 6 步建出来的账号密码对不上：

```bash
sudo nano /opt/beijing-wuzi-campus-guide/database/01-init.sql
```

把里面所有 `__DB_PASS__` 占位符替换成第 4.2 步设置的新密码（共两处），保存。

> 也可以反过来：`01-init.sql` 不动，`.env` 里保留原密码。这样能跑，但请确保密码只在你自己手里。

## 5. 停掉旧服务

按第 0 步查到的托管方式操作：

**如果是 systemd 服务：**

```bash
sudo systemctl stop 旧服务名
sudo systemctl disable 旧服务名
```

**如果是 pm2：**

```bash
pm2 stop all
pm2 delete all
pm2 save
```

**如果是裸 node 进程（没有托管）：**

```bash
sudo kill 12345          # 换成第 0 步记下的 pid
```

**确认 55 端口已空出来：**

```bash
sudo ss -lntp | grep ':55 ' || echo "55 端口已空闲"
```

> 如果输出不是「55 端口已空闲」，说明还有别的进程占着，回到第 0 步重新查。

**顺带备份旧数据**（保险起见，强烈建议）：

```bash
# 旧项目的数据库如果也叫 bwz_campus_guide
sudo mysqldump -u root -p bwz_campus_guide > ~/old_db_backup_$(date +%F).sql
# 旧项目的上传文件
sudo tar czf ~/old_uploads_$(date +%F).tar.gz /旧项目路径/public/uploads
```

## 6. 部署新版本

```bash
cd /opt/beijing-wuzi-campus-guide/deploy
sudo chmod +x deploy.sh
sudo ./deploy.sh
```

脚本会自动完成：装依赖 → 建库建账号 → 导入数据 → 注册 systemd 服务 → 启动 → 健康检查。

看到最后打印出站点地址就成功了。

### 如果数据库里已经有旧版的数据

脚本检测到表已存在时会**跳过 SQL 导入**（不会覆盖你现有的内容），随后会用 `database/content.json` 同步一次内容数据（建筑信息、周边设施、分类、提示语、校历等，详见 [10. 以后怎么更新内容](#内容改了但服务器上看不到重要)）。

如果库是很老的版本，还需要补字段（v1.7 / v1.8 加的功能，旧库没有）：

```bash
cd /opt/beijing-wuzi-campus-guide/app
sudo -u root node server/scripts/migrate-v17.mjs
sudo -u root node server/scripts/migrate-v18.mjs
```

输出「已添加 xxx」或「已存在，跳过」都正常。

## 7. 验证

```bash
# 服务状态
sudo systemctl status bwz-campus --no-pager

# 健康检查
curl -s http://127.0.0.1:55/api/health
# 期望：{"ok":true,...}

# 首页能拿到
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:55/
# 期望：200

# 模型文件在
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:55/models/campus.glb
# 期望：200
```

外部访问打不开的话，放行端口：

```bash
# Ubuntu / Debian
sudo ufw allow 55/tcp
sudo ufw reload

# CentOS / RHEL / 阿里云 Linux
sudo firewall-cmd --add-port=55/tcp --permanent
sudo firewall-cmd --reload
```

**云服务器还要去控制台的「安全组」里放行 55 端口**，这一步在服务器内部改不了。

## 9.（可选）用 Nginx 走 80 / 443

想让用户直接访问 `http://你的域名`（不带端口），装 Nginx 反代：

```bash
sudo apt-get install -y nginx
sudo cp /opt/beijing-wuzi-campus-guide/deploy/nginx.conf.example /etc/nginx/sites-available/bwz-campus
sudo ln -sf /etc/nginx/sites-available/bwz-campus /etc/nginx/sites-enabled/bwz-campus
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

然后把 `.env` 的 `SERVE_PORT` 改成 `5055`（避免和别的服务抢 55），重启：

```bash
sudo systemctl restart bwz-campus
```

证书（HTTPS）：

```bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名
```

## 10. 以后怎么更新内容

### 只改内容（绝大多数情况）

**不用碰服务器**。浏览器进 `/admin` 改，保存即生效。

### 改完前端界面要更新代码

在你自己的电脑上：

```bash
cd My_school/My_school
npm run build
```

然后把这三处同步到服务器（`dist` 整个目录 + `src` 源码 + 可能改过的 `server`）：

```bash
# 在你电脑上
scp -r dist 你的用户名@你的服务器IP:/tmp/new-dist
scp -r src  你的用户名@你的服务器IP:/tmp/new-src
```

在服务器上：

```bash
sudo systemctl stop bwz-campus
sudo rsync -a --delete /tmp/new-dist/ /opt/beijing-wuzi-campus-guide/app/dist/
sudo rsync -a /tmp/new-src/  /opt/beijing-wuzi-campus-guide/app/src/
sudo systemctl start bwz-campus
sudo systemctl status bwz-campus --no-pager
```

> `--delete` 会清掉 dist 里的旧文件，这是对的（旧的 js/css 带 hash，不删会越堆越多）。
> **但千万别对 `app/public/uploads` 用 `--delete`**，那是用户传的照片。

### 改了模型

1. 在 Blender 里改 `blender/北京物资学院_白膜.blend`
2. 用 `app/tools/export-model.py` 导出新的 `campus.glb`
3. 同时替换这两处：
   - `app/public/models/campus.glb`
   - 重新 `npm run build` 后，`dist/models/campus.glb` 会跟着更新
4. 改 `app/src/modelVersion.js` 里的 `MODEL_VERSION`（换一个新字符串），强制浏览器重新下载模型
5. 重新 build 并按上面的方式同步 `dist`

### 改了后端代码（server/ 目录）

```bash
# 同步文件后重启即可，不用 build
sudo systemctl restart bwz-campus
```

### 改了数据库结构

**正常情况下不用管**：服务启动时会自动自检并补齐结构（`app/server/schema.js`），日志里会打印：

```
[schema] 表结构已是最新
```

或者：

```
[schema] 已补 location_submissions.author_name
[schema] 已补 location_submissions.photo_*
```

所以「整包覆盖 + `sudo systemctl restart bwz-campus`」这条路也是安全的。

如果需要手动补一次（比如自检被数据库账号权限挡住，日志出现 `[schema] 补 xxx 失败`）：

```bash
cd /opt/beijing-wuzi-campus-guide/app
sudo node server/scripts/repair-schema.mjs
```

对应到 npm：

```bash
npm run db:repair     # 补结构（安全，重复执行无副作用）
npm run db:migrate    # 跑全部迁移脚本（v12 / v17 / v18 / v19，同样幂等）
```

**典型症状对照**：

| 前台表现 | 真实原因 | 解决 |
| --- | --- | --- |
| 投稿/上传照片提示「服务器内部错误」 | 库里 `location_submissions` 缺 `photo_*` 字段 | 重启服务让它自检，或 `npm run db:repair` |
| 后台保存建筑报 500 | 缺 `buildings.aliases` 等字段 | 同上 |
| 日志出现 `ER_BAD_FIELD_ERROR` | 库结构落后于代码 | 同上 |

从 v1.5 起，遇到这类错误接口会返回 `code: "SCHEMA_OUTDATED"`（而不是含糊的「服务器内部错误」），日志里也会明确写「数据库结构落后于代码，请运行 db:repair」。

### 内容改了，但服务器上看不到（重要）

**症状**：在自己电脑上把建筑信息、周边设施、分类、提示语、校历都改好了，网页本地一切正常；把整个 `beijing-wuzi-campus-guide` 覆盖上传到服务器、跑完 `update.sh`，服务器上却还是老内容。

**原因**：`deploy.sh` 只在「库里一张表都没有」时才导入 SQL 快照（`database/bwz_campus_guide.sql`），`update.sh` 完全不碰数据。而且那份 SQL 快照是发布包生成那一刻导出的，之后在本机后台改的内容都不在里面。

**现在的解决办法**（v1.5 起已内置）：内容数据单独导出一份 `database/content.json`，更新时用 `sync-content.mjs` 覆盖同步进库。

发行包里已经带好了 `database/content.json`，所以 **`sudo ./update.sh` 会自动同步**，你不需要额外操作。

如果只改了内容、想单独同步一次（不碰前端和后端）：

```bash
cd /opt/beijing-wuzi-campus-guide/app
# 先看看会改什么（不写库）
node server/scripts/sync-content.mjs --dry-run
# 确认无误再正式写
node server/scripts/sync-content.mjs
```

常用参数：

```bash
node server/scripts/sync-content.mjs --only=buildings,settings   # 只同步指定表
CONTENT_FILE=/tmp/content.json node server/scripts/sync-content.mjs  # 指定数据文件
```

**同步范围**（只覆盖这 7 张内容表）：

| 表 | 内容 |
| --- | --- |
| `categories` | 地图分类（名称/图标/颜色） |
| `buildings` | 建筑全部信息：简介、楼层、设备、联系方式、**周边设施**、校历、别名、标点坐标 |
| `settings` | 站点设置（配色预设、数字校园开关、模型变换） |
| `tips` | 首页提示语 |
| `search_aliases` | 搜索别名（114 条） |
| `calendar_items` | 校历事件 |
| `calendar_meta` | 校历标题 |

**不会被覆盖**（服务器上的这些数据保持原样）：`album_photos`（相册照片）、`album_folders`、`location_submissions`（投稿）、`audit_logs`（操作日志）、`admins`（后台账号）。

**注意**：这是「本机覆盖服务器」的单向同步。如果有人在服务器后台改过建筑信息而本机没改，跑完会被本机的版本盖掉。规范做法是**内容只在本机改**，改完导出 `content.json` 再上传。

本机改完内容后，记得重新生成 `content.json`（否则包里带的还是旧数据）：

```bash
cd app
npm run content:export   # 写 ../database/content.json
npm run content:diff     # 校验：本地库与 content.json 应该「未变 N、更新 0」
```

## 常见问题

**Q：启动后访问是 502 / 拒绝连接**
先 `sudo systemctl status bwz-campus --no-pager` 看有没有真的在跑，再看 `journalctl -u bwz-campus -n 50`。最常见是数据库连不上（`.env` 的密码和 `01-init.sql` 建的不一致）。

**Q：页面打开一片空白，控制台 404**
`dist` 没同步全。确认 `/opt/beijing-wuzi-campus-guide/app/dist/index.html` 存在，`dist/assets/` 里有一堆 js/css。

**Q：三维模型加载不出来（一直转圈）**
检查 `/opt/.../app/dist/models/campus.glb` 是否存在、大小是不是 4111008 字节左右。服务端是从 `dist/models` 提供模型的。

**Q：后台登录提示「尝试次数过多」**
连续错 5 次会锁 15 分钟。急着用就重启服务解锁：`sudo systemctl restart bwz-campus`。

**Q：照片上传后前台看不到**
看 `app/public/uploads/album/` 下有没有新文件，以及服务日志有没有写入权限错误。`public/uploads` 目录属主得是运行服务的用户（用本脚本部署时是 root，没问题）。

**Q：想整个重来（清空数据）**
```bash
sudo mysql -e "DROP DATABASE bwz_campus_guide;"
cd /opt/beijing-wuzi-campus-guide/deploy && sudo ./deploy.sh
```
⚠️ 这会删掉所有后台改过的内容和照片记录（照片文件还在磁盘上，但数据库记录没了）。
